# Задание 1

Ваша компания владеет AS 100 и имеет два подключения к сети Интернет с использованием протокола BGP.

Канал к ISP А (AS200) дешевый и с большой пропускной способностью.
Канал к ISP B (AS300) меньше и менее надежный.
Сетевое оборудование Cisco.

Стоит задача - максимально использовать первый канал для доступа в сеть Интернет.

Выберите технологию управления исходящим трафиком, которая с наименьшими затратами позволит решить эту задачу.
Обоснуйте свой выбор.
Приведите пример настройки выбранной технологии, основываясь на информации отображенной на схеме.
Приведите ответ в свободной форме.

# ОТВЕТ:

Для управления исходящим трафиком в AS100 с двумя провайдерами оптимальной технологией является BGP Local Preference. Позволяет задать приоритет для путей, полученных от каждого провайдера, и транслировать это предпочтение на все маршрутизаторы внутри сети.

Обоснование выбора

Целенаправленное влияние на исходящий трафик: Local Preference работает внутри AS и напрямую влияет на выбор выходного пути. Установив более высокий Local Preference для маршрутов, полученных от ISP A (AS200), весь трафик к внешним сетям будет направляться через этот канал.

Минимальные затраты: Эта технология не требует дополнительного оборудования или лицензий. Настройка выполняется на существующем оборудовании Cisco с помощью стандартных средств BGP (route-maps).

Предсказуемость и согласованность: Атрибут Local Preference распространяется через iBGP-сессии внутри AS. Таким образом, даже если трафик поступает на пограничный маршрутизатор R3, он узнает от R1, что выход через ISP A предпочтительнее, и направит трафик через R1 .

Простота реализации: Управление Local Preference находится полностью в зоне ответственности и дает мгновенный результат .


На маршрутизаторе R1 (AS100), который имеет прямое eBGP-соединение с ISP A, необходимо применить политику к маршрутам, получаемым от этого провайдера.

1. Создаем route-map, который устанавливает высокий Local Preference для всех маршрутов от ISP A:

route-map SET_PREF_ISP_A permit 10
 set local-preference 200

По умолчанию Local Preference равен 100. Установка значения 200 делает маршруты от ISP A более предпочтительными .

2. Применяем этот route-map к BGP-соседу (ISP A):

router bgp 100
 neighbor 10.10.10.1 route-map SET_PREF_ISP_A in

3. Настраиваем резервный канал через ISP B (AS300) с более низким приоритетом:

Для второго канала, который является резервным, можно оставить Local Preference по умолчанию (100) или явно установить меньшее значение, например, 50, чтобы гарантировать его использование только при отказе основного канала.

route-map SET_PREF_ISP_B permit 10
 set local-preference 50

Эта политика применяется к соседу ISP B (AS300) на маршрутизаторе R4:

router bgp 100
 neighbor 20.20.20.1 route-map SET_PREF_ISP_B in

 Установленный атрибут Local Preference будет передан от R1 к R4 и наоборот. Это обеспечит единую политику выбора исходящего канала для всей сети AS100

# Задание 2

Топология и компания те же.

Решив вопрос с исходящим трафиком, через некоторое время вы заметили, что большая часть входящего трафика поступает в вашу сеть от ISP B (AS300).
Вас такое положение не устраивает. Теперь необходимо решить вопрос с входящим трафиком.

Выберите технологию управления входящим трафиком, которая с наименьшими затратами позволит решить эту задачу.
Обоснуйте свой выбор.
Приведите пример настройки выбранной технологии, основываясь на информации отображенной на схеме.
Приведите ответ в свободной форме.

# ОТВЕТ:

Оптимальной технологией является BGP AS Path Prepending.

Обоснование выбора

Влияние на входящий трафик: В отличие от Local Preference, которая работает только внутри AS и влияет на исходящий трафик, AS Path Prepending воздействует на соседние автономные системы. "Удлиняя" AS_PATH для маршрутов, анонсируемых через ISP A, Вы делаете этот путь менее привлекательным для удаленных сетей. Однако в задаче нужно улучшить использование первого канала (ISP A) для входящего трафика. Следовательно, мы должны укоротить путь через ISP A (оставить как есть) и искусственно удлинить путь через ISP B (AS300), чтобы удаленные маршрутизаторы выбирали для доступа к сетям более короткий и предпочтительный маршрут через ISP A.

Минимальные затраты: Эта технология не требует покупки дополнительного оборудования, лицензий или изменения физической топологии. Настройка выполняется стандартными средствами BGP на существующих пограничных маршрутизаторах (R1 и R4).

Простота и предсказуемость: AS Path Prepending является наиболее распространенным и простым методом управления входящим трафиком в многодоменных BGP-сетях. Он не зависит от политик соседей (в отличие от MED, который провайдеры часто игнорируют) и работает на уровне глобальной таблицы маршрутизации.

Селективное воздействие: Мы применим prepending только к анонсам Ваших PI-блоков через ISP B, оставив анонсы через ISP A без изменений. Это заставит внешние сети видеть путь через AS300 более длинным (например, "100 300 300 300" вместо "100 200") и выбрать AS200 в качестве основного входящего канала.

Пример настройки на оборудовании Cisco (R4)
На маршрутизаторе R4 (AS100), который имеет eBGP-соединение с ISP B (AS300), необходимо модифицировать анонсируемые маршруты таким образом, чтобы добавить повторяющиеся номера AS300 в AS_PATH.

1. Создаем route-map для анонса в сторону ISP B с добавлением трех копий AS300:


route-map PREPEND_TO_ISP_B permit 10
 set as-path prepend 300 300 300

Команда set as-path prepend добавляет указанные номера AS в начало AS_PATH. В результате для маршрутов, анонсируемых через R4, AS_PATH станет выглядеть как 100 300 300 300 (или, в зависимости от формата отображения, 300 300 300 100). Это делает путь через ISP B на 3 шага длиннее, чем путь через ISP A (где AS_PATH будет просто 100 200).

2. Применяем этот route-map к анонсам в сторону соседа ISP B (AS300):

router bgp 100
 neighbor 20.20.20.1 route-map PREPEND_TO_ISP_B out

3. Настраиваем анонсы через ISP A (R1) без изменений:

На маршрутизаторе R1 анонсы в сторону ISP A остаются с оригинальным AS_PATH:


router bgp 100
 neighbor 10.10.10.1 route-map ALLOW_AS_IS out   ! Можно вообще не применять политику или применить route-map без изменений

 Таким образом, после применения этой политики удаленные сети будут видеть два пути к Вашим PI-блокам:

Через AS200: 100 200 (длина 2)

Через AS300: 100 300 300 300 (длина 4)

BGP-процессы на внешних маршрутизаторах выберут более короткий путь через AS200, и большая часть входящего трафика начнет поступать через основной, более дешевый и производительный канал ISP A.

# Задание 3

Топология и компания те же.

Решение, выбраное в Задании 2, помогло, но недостаточно. Вы пообщались с провайдерами и выяснили, что у обоих провайдеров есть политики управления трафиком, определяемые community.

ISP A AS_200 community: 200:xxx - Local-pref to your AS

ISP B AS_300 community: 300:xxx - Local-pref to your AS

А также Вы узнали, что между ними есть прямая связь. На этом стыке установлен атрибут local-pref со значением 200 с обоих сторон.

Теперь необходимо воспользоваться полученым знанием, чтобы улучшить свои политики управления входящим трафиком.

Выберите технологию управления входящим трафиком которая позволит решить эту задачу.
Обоснуйте свой выбор.
Приведите пример настройки выбранной технологии основываясь на информации отображенной на схеме.
Приведите ответ в свободной форме.

# ОТВЕТ:

Для решения проблемы с входящим трафиком в новых условиях, когда провайдеры предоставляют возможность управления через BGP Community, оптимальной технологией является использование BGP Community для влияния на Local Preference у провайдеров.

Обоснование выбора
Прямое воздействие на политику провайдера: В отличие от AS Path Prepending, который работает косвенно и зависит от алгоритмов выбора пути на множестве удаленных AS, использование Community позволяет напрямую попросить провайдера изменить атрибут Local Preference для Ваших маршрутов внутри его сети. Это дает гораздо более предсказуемый и гарантированный результат.

Решение проблемы с прямой связью между провайдерами: Ключевая информация — между ISP A и ISP B существует прямая связь, и на этом стыке установлен Local Preference = 200 с обеих сторон. Это означает, что:

Когда ISP B получает трафик для Ваших сетей через прямую связь от ISP A, он видит этот маршрут с Local Preference 200 (высокий приоритет).

По умолчанию ISP B будет предпочитать отдавать трафик Вам именно через эту прямую связь (то есть через ISP A), а не через Ваш прямой канал к ISP B, если Вы не скорректируете приоритеты.

Теперь, используя Community от ISP B (300:xxx), Вы можете попросить ISP B повысить Local Preference для маршрутов, полученных непосредственно через Ваш канал (R4), чтобы он стал выше, чем Local Preference для маршрутов, приходящих от ISP A через прямую связь.

Точная настройка: Эта технология позволяет установить желаемое значение Local Preference у провайдера (например, 150 или 250). Установив его выше 200, Вы гарантируете, что ISP B будет направлять трафик к Вам напрямую через Ваш канал, а не через прямую связь с ISP A. Установив ниже 200, Вы можете наоборот "переложить" трафик на ISP A, но в Вашей задаче — улучшить использование основного канала ISP A для входящего трафика, поэтому нам нужно, чтобы оба провайдера предпочитали направлять трафик к Вам через ISP A.

Стратегия решения
Чтобы максимально использовать первый канал (ISP A) для входящего трафика:

Через ISP A (AS200): Оставляем анонс без изменений. ISP A будет получать Ваши маршруты напрямую от R1. Учитывая, что у ISP A нет конкурентного маршрута через ISP B с более высоким Local Preference (мы сейчас настроим так, чтобы через ISP B предпочитали ISP A), ISP A будет использовать Ваш прямой канал.

Через ISP B (AS300): Используем Community, чтобы попросить ISP B понизить Local Preference для маршрутов, полученных непосредственно от Вас (через R4), до значения ниже 200 (например, 150). Тогда ISP B увидит:

Маршрут через прямое соединение с ISP A: Local Preference = 200 (по умолчанию со стыка)

Маршрут через Ваш прямой канал: Local Preference = 150 (установленный Вами через Community)

Согласно BGP, ISP B выберет маршрут с более высоким Local Preference, то есть путь через ISP A. Таким образом, весь входящий трафик от обоих провайдеров и их клиентов будет приходить через ISP A.

Пример настройки на оборудовании Cisco (R4)
На маршрутизаторе R4 (AS100), который анонсирует Ваши PI-блоки в сторону ISP B (AS300), необходимо добавить Community, указывающее провайдеру желаемое значение Local Preference.

1. Создаем route-map для анонса в сторону ISP B с установкой Community:

text
route-map SET_COMMUNITY_TO_ISP_B permit 10
 set community 300:150
Пояснение: Community 300:150 интерпретируется провайдером ISP B как просьба установить Local Preference для этих маршрутов равным 150. Конкретное значение может отличаться в зависимости от документации провайдера (некоторые используют 300:90 для low pref, 300:200 для high pref), но в данном случае мы используем условное обозначение из условия задачи.

2. Применяем route-map к анонсам в сторону соседа ISP B:

text
router bgp 100
 neighbor 20.20.20.1 route-map SET_COMMUNITY_TO_ISP_B out
 neighbor 20.20.20.1 send-community
Пояснение: Команда send-community обязательна, чтобы маршрутизатор передавал Community-атрибуты соседу.

3. Настраиваем анонсы через ISP A (R1) без изменений или с повышающим Community (по желанию):

На R1, если требуется дополнительно гарантировать приоритет, можно также отправить Community с высоким значением, но это не обязательно, так как основной механизм уже настроен через ISP B.

text
router bgp 100
 neighbor 10.10.10.1 route-map ALLOW_AS_IS out   ! Без изменений или с community 200:200 для повышения
 neighbor 10.10.10.1 send-community
Итоговый эффект
После применения этой политики:

ISP B будет иметь два пути к Вашим сетям:

Через прямую связь с ISP A: Local Preference = 200 (предпочтительный).
Напрямую через R4: Local Preference = 150 (менее предпочтительный).
ISP B выберет путь через ISP A.

ISP A будет иметь только прямой путь через R1 и будет использовать его.

В результате весь входящий трафик от обоих провайдеров и их клиентов будет поступать через основной канал ISP A, что полностью решает задачу максимального использования первого канала с минимальными затратами (только настройка Community). Резервный канал через ISP B останется активным, но будет использоваться только в случае отказа основного канала.

# Задание 4*

В указанной топологии вы управляте маршрутизатором ISPA в AS200

Требуется настроить обработку комьюнити 200:xxx для изменения Local Prefernece анонсов от клиента из AS100, которые тегированы данным community. Возможные значения xxx:

300 - Local Prefernece 300

600 - Local Preference 600

Создайте нужное количество community list

Создайте route-map

Примените route-map на стык с клиентом

Приведите ответ в свободной форме.

# ОТВЕТ:

Обоснование выбора
Поскольку клиент (AS100) теперь может тегировать свои анонсы Community вида 200:xxx, Ваша задача как провайдера — интерпретировать эти Community и устанавливать соответствующий Local Preference для маршрутов, полученных от этого клиента. Это позволяет клиенту влиять на выбор пути внутри Вашей AS, что особенно актуально с учетом наличия прямой связи между ISP A и ISP B.

Технология включает:

Community List для идентификации приходящих Community.

Route-map для сопоставления Community с нужным значением Local Preference.

Применение route-map на eBGP-сессии с клиентом (AS100).

Конфигурация R3.

! Создаем community lists
ip community-list 1 permit 200:300
ip community-list 2 permit 200:600

! Создаем route-map
route-map CLIENT_POLICY_IN permit 10
 match community 1
 set local-preference 300
!
route-map CLIENT_POLICY_IN permit 20
 match community 2
 set local-preference 600
!
route-map CLIENT_POLICY_IN permit 30
 ! Default action - permit all others without changes
!

! Применяем к BGP-соседу
router bgp 200
 neighbor 10.10.10.2 route-map CLIENT_POLICY_IN in

 Теперь клиент (AS100) может тегировать свои анонсы, отправляемые в сторону ISP A:

Если клиент хочет, чтобы ISP A понизил приоритет своих маршрутов (например, чтобы трафик шел через ISP B), он отправляет Community 200:300 (Local Pref = 300 — ниже, чем значение 600).

Если клиент хочет, чтобы ISP A повысил приоритет (чтобы трафик шел через ISP A), он отправляет Community 200:600 (Local Pref = 600).

Учитывая, что на прямой связи между ISP A и ISP B установлен Local Preference = 200 с обеих сторон:

Если клиент просит установить Local Preference = 300 у ISP A, то ISP A будет предпочитать прямой путь к клиенту (через R1) вместо пути через ISP B (где Local Pref = 200).

Если клиент просит установить Local Preference = 600, это еще сильнее закрепит приоритет прямого пути.

Таким образом, клиент получает гибкий инструмент управления входящим трафиком через сеть.

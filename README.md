# ОТВЕТ:

Для управления исходящим трафиком в AS100 с двумя провайдерами оптимальной технологией является BGP Local Preference. Позволяет задать приоритет для путей, полученных от каждого провайдера, и транслировать это предпочтение на все маршрутизаторы внутри сети.

Обоснование выбора

Целенаправленное влияние на исходящий трафик: Local Preference работает внутри AS и напрямую влияет на выбор выходного пути. Установив более высокий Local Preference для маршрутов, полученных от ISP A (AS200), весь трафик к внешним сетям будет направляться через этот канал.

Минимальные затраты: Эта технология не требует дополнительного оборудования или лицензий. Настройка выполняется на существующем оборудовании Cisco с помощью стандартных средств BGP (route-maps).

Предсказуемость и согласованность: Атрибут Local Preference распространяется через iBGP-сессии внутри AS. Таким образом, даже если трафик поступает на пограничный маршрутизатор R3, он узнает от R1, что выход через ISP A предпочтительнее, и направит трафик через R1 .

Простота реализации: Управление Local Preference находится полностью в зоне ответственности и дает мгновенный результат .


На маршрутизаторе R1 (AS100), который имеет прямое eBGP-соединение с ISP A, необходимо применить политику к маршрутам, получаемым от этого провайдера.

1. Создаем route-map, который устанавливает высокий Local Preference для всех маршрутов от ISP A:

route-map SET_PREF_ISP_A permit 10
 set local-preference 200

По умолчанию Local Preference равен 100. Установка значения 200 делает маршруты от ISP A более предпочтительными .

2. Применяем этот route-map к BGP-соседу (ISP A):

router bgp 100
 neighbor 10.10.10.1 route-map SET_PREF_ISP_A in

3. Настраиваем резервный канал через ISP B (AS300) с более низким приоритетом:

Для второго канала, который является резервным, можно оставить Local Preference по умолчанию (100) или явно установить меньшее значение, например, 50, чтобы гарантировать его использование только при отказе основного канала.

route-map SET_PREF_ISP_B permit 10
 set local-preference 50

Эта политика применяется к соседу ISP B (AS300) на маршрутизаторе R4:

router bgp 100
 neighbor 20.20.20.1 route-map SET_PREF_ISP_B in

 Установленный атрибут Local Preference будет передан от R1 к R4 и наоборот. Это обеспечит единую политику выбора исходящего канала для всей сети AS100

# ОТВЕТ:

Оптимальной технологией является BGP AS Path Prepending.

Обоснование выбора

Влияние на входящий трафик: В отличие от Local Preference, которая работает только внутри AS и влияет на исходящий трафик, AS Path Prepending воздействует на соседние автономные системы. "Удлиняя" AS_PATH для маршрутов, анонсируемых через ISP A, Вы делаете этот путь менее привлекательным для удаленных сетей. Однако в задаче нужно улучшить использование первого канала (ISP A) для входящего трафика. Следовательно, мы должны укоротить путь через ISP A (оставить как есть) и искусственно удлинить путь через ISP B (AS300), чтобы удаленные маршрутизаторы выбирали для доступа к Вашим сетям более короткий и предпочтительный маршрут через ISP A.

Минимальные затраты: Эта технология не требует покупки дополнительного оборудования, лицензий или изменения физической топологии. Настройка выполняется стандартными средствами BGP на существующих пограничных маршрутизаторах (R1 и R4).

Простота и предсказуемость: AS Path Prepending является наиболее распространенным и простым методом управления входящим трафиком в многодоменных BGP-сетях. Он не зависит от политик соседей (в отличие от MED, который провайдеры часто игнорируют) и работает на уровне глобальной таблицы маршрутизации.

Селективное воздействие: Мы применим prepending только к анонсам Ваших PI-блоков через ISP B, оставив анонсы через ISP A без изменений. Это заставит внешние сети видеть путь через AS300 более длинным (например, "100 300 300 300" вместо "100 200") и выбрать AS200 в качестве основного входящего канала.

Пример настройки на оборудовании Cisco (R4)
На маршрутизаторе R4 (AS100), который имеет eBGP-соединение с ISP B (AS300), необходимо модифицировать анонсируемые маршруты таким образом, чтобы добавить повторяющиеся номера AS300 в AS_PATH.

1. Создаем route-map для анонса в сторону ISP B с добавлением трех копий AS300:

text
route-map PREPEND_TO_ISP_B permit 10
 set as-path prepend 300 300 300
Пояснение: Команда set as-path prepend добавляет указанные номера AS в начало AS_PATH. В результате для маршрутов, анонсируемых через R4, AS_PATH станет выглядеть как 100 300 300 300 (или, в зависимости от формата отображения, 300 300 300 100). Это делает путь через ISP B на 3 шага длиннее, чем путь через ISP A (где AS_PATH будет просто 100 200).

2. Применяем этот route-map к анонсам в сторону соседа ISP B (AS300):

text
router bgp 100
 neighbor 20.20.20.1 route-map PREPEND_TO_ISP_B out
3. Настраиваем анонсы через ISP A (R1) без изменений:

На маршрутизаторе R1 анонсы в сторону ISP A остаются с оригинальным AS_PATH:

text
router bgp 100
 neighbor 10.10.10.1 route-map ALLOW_AS_IS out   ! Можно вообще не применять политику или применить route-map без изменений
